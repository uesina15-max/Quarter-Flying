# Sound Lite — 사운드 시스템 범위 정의서

**작성일**: 2026-09-10
**문서 상태**: 범위/철학 문서. `docs/VFX_LITE_PLAN.md`와 같은 단계로, 구현 계획서를 쓰기 전에 **"무엇을 만들고 무엇을 만들지 않을 것인가"를 먼저 고정**하기 위한 것이다.

> **개정(2026-09-10)**: §6의 미해결 항목이 **전부 확정됐다** — §6.2 **(b)** Scene Editor Play에서도 파이썬이 액션을 재생 / §6.2.1 **(b2)** 전용 `ActionPlayerComponent`(필드 3개) 신설 / §6.1 게임 빌드 사운드는 **v1 제외** / §6.3 **WAV만** / §6.4 클립 경로는 **`.action.json` 기준 상대 경로**. 구현은 [docs/SOUND_LITE_IMPLEMENTATION_PLAN.md](SOUND_LITE_IMPLEMENTATION_PLAN.md)로 넘어간다.

> **이 문서가 VFX Lite의 순서를 따르는 이유**: VFX Lite에서 범위를 먼저 고정하고 그 전제를 실제 코드와 대조한 결과, 착수 전에 잘못된 전제 7건을 잡았다(`VFX_LITE_PLAN.md` §7). 사운드는 특히 **3D 감쇠 → 리스너 → 오클루전 → 리버브 존 → 믹서 버스**로 번지기 쉬운 영역이라, 제외 목록이 포함 목록보다 중요하다.

---

## 0. 한 줄 정의

> 사운드를 범용 오디오 엔진이 아니라 **"액션의 특정 프레임에서 소리 하나를 낸다"** 로 제한된 **작은 사운드 시스템(Sound Lite)** 하나로 정의한다.

기준은 "오디오가 무엇을 할 수 있는가"가 아니라 **"타격음 하나를 프레임에 맞춰 넣고 들어보는 데 무엇이 최소로 필요한가"** 다.

---

## 1. 배경 — 지금 있는 것과 없는 것

전부 실측이다(근거는 부록). **VFX/프리팹 때와 달리 "자리"가 이미 상당히 깔려 있다.**

### 1.1 이미 있는 것 — 생각보다 많다

- **`EventType.SOUND`이 이미 존재한다** — [engine/editor/core/action_data.py](../engine/editor/core/action_data.py)의 `EventType` enum에 `Hit`/`Effect`/**`Sound`**/`CameraShake` 넷이 있고, 이벤트 타임라인의 UI 마커 색(`#44aaff`)까지 배정되어 있다. 즉 **타임라인에 사운드 이벤트를 찍는 자리는 만들 필요가 없다.**
- **`ActionEvent.params: dict`가 자유형이다** — `frame`/`type`/`params` 구조라, 클립 경로·볼륨 같은 값을 담는 데 **자료구조 변경이 필요 없다.**
- **`.action.json` 포맷도 안 바뀐다** — `ActionData.to_dict()`가 이벤트의 `params`를 그대로 직렬화하고 `from_dict()`가 되읽는다. VFX가 "새 `.vfx.json`을 발명하지 않는다"고 했던 것과 같은 상황이 여기서는 **이미 성립해 있다.**
- **발화시킬 지점이 정확히 하나 있다** — [engine/editor/panels/animation_preview.py](../engine/editor/panels/animation_preview.py)의 `_on_tick()`이 재생 타이머가 프레임을 전진시키는 **유일한 곳**이고, 여기서 `frame_changed`를 emit한다. `motion_editor.py`가 이 시그널을 이벤트 타임라인/모션 그래프와 양방향으로 묶어둔 상태다.
- **QtMultimedia를 쓸 수 있다** — 이 환경의 PySide6에 `QSoundEffect`/`QMediaPlayer`/`QAudioOutput`이 실제로 import된다(직접 확인). 즉 **엔진에 오디오 백엔드를 만들지 않고도 소리를 낼 수 있다.**
- **`AssetType::Audio` enum이 있다** — [engine/asset/AssetHandle.h](../engine/asset/AssetHandle.h). 다만 이를 참조하는 코드는 없다 — 프리팹 착수 전 `AssetType::Prefab`이 그랬던 것과 **정확히 같은 상태**다.
- **"이 엔티티는 어떤 액션을 쓴다"는 데이터가 이미 있다(단, 아무도 읽지 않는다)** — `AIComponent`가 `idle_action`/`attack_action`/`hit_action` 문자열 필드(기본값 `"Idle.action"` 등)와 `AIState` enum(Idle/Patrol/Chase/Attack/Return)을 갖고 리플렉션에도 등록되어 있다([engine/ecs/Components.h](../engine/ecs/Components.h), [engine/ecs/Reflection.cpp](../engine/ecs/Reflection.cpp)). **그러나 이 필드들을 읽는 시스템이 하나도 없다** — 정의와 등록 두 곳에만 존재한다. §6.2의 결정에 직접 영향을 준다.
- **Play/Pause/Stop이 엔진까지 연결되어 있다** — `main.py`의 `_on_play`/`_on_pause`/`_on_stop`이 각각 `World::Play()`/`Pause()`/`Stop()`을 호출한다. `World`는 `EditorState`(Edit/Play/Pause)를 갖고 Play 진입 시 PIE 스냅샷을 뜬다.
- **Play Mode의 창 클래스 충돌 버그는 이미 고쳐져 있다** — `ERROR_CLASS_ALREADY_EXISTS`를 "이미 등록됨"으로 처리해 기존 클래스를 재사용한다([engine/platform/Win32Platform.cpp](../engine/platform/Win32Platform.cpp)). `CLAUDE.md`의 "알려진 버그" 항목은 그보다 이른 2026-08-10 기록이라 낡았다.

### 1.2 없는 것 — 전부 0건

- **오디오 백엔드 일체.** OpenAL/miniaudio/XAudio2/WASAPI 어느 것도 없다. **엔진에는 소리를 낼 방법 자체가 없다.**
- WAV/OGG 디코더.
- **`.action.json`을 읽는 C++ 경로.** `ActionData`/`ActionEvent`/`ActionSection`은 **파이썬 에디터 전용 자료구조**이고, `engine/animation/`(C++)에는 Action이나 Event라는 개념 자체가 없다.
- 재생 중 프레임에 맞춰 이벤트를 발화시키는 **런타임**(에디터 미리보기든 게임이든).
- 에셋 임포트 GUI. `engine/asset/`은 여전히 호출부 없는 고아 모듈이다.
- 디스크에 존재하는 `.action.json` 파일 — 아직 하나도 없다.

### 1.3 이 배경이 뜻하는 것

**"이 프레임에 이 소리" 라는 저작 경험 자체는 파이썬만으로 완성할 수 있다.** 이벤트 타입·파라미터 자리·직렬화·프레임 배선·재생 타이머·오디오 API가 전부 이미 있고, 없는 것은 **그 여섯 개를 잇는 코드**뿐이다.

반대로 **게임 빌드에서 나는 소리**는 위 1.2의 항목을 거의 전부 새로 만들어야 한다. 이 둘의 비용 차이가 이 문서의 모든 결정을 지배한다(§4.3, §6.1).

## 2. 확정 범위 — 파라미터 목록

아래 **3개 값이 전체 범위다. 더 늘리지 않는다** — §3의 제외 목록과 쌍을 이룬다.

### 2.1 클립 (Clip)
| 값 | 의미 |
|---|---|
| Clip | 재생할 오디오 파일 경로 |
| Volume | 재생 음량 (0.0 ~ 1.0) |

### 2.2 변주 (Variation)
| 값 | 의미 |
|---|---|
| Volume ± | 음량에 적용할 변동폭 |

> **변주를 범위 안에 넣은 이유**: 타격음처럼 짧은 시간에 반복 재생되는 소리는 매번 완전히 동일하면 **기계적으로 들린다**. 값 하나로 그 문제를 상당 부분 완화하는, 비용 대비 효과가 큰 항목이다. 반대로 이게 없으면 사운드 담당자가 같은 소리의 변형 클립을 여러 개 만들어 돌려쓰게 되는데, 그건 §3에서 제외한 "사운드 큐/랜덤 클립 세트"를 부르는 경로다.

> **개정(2026-09-10, 착수 직전 실측)**: 초안은 `Pitch`/`Pitch ±`를 포함해 **5개 값**이었으나 **3개로 줄인다.** `QSoundEffect`에 **음정/재생속도에 해당하는 속성이 아예 없다는 것을 직접 확인했다**(가진 것은 `volume`/`loopCount`/`source`/`muted`/`status`뿐). §6.3에서 "문서 기준이지 실측이 아니다"라고 표시해둔 바로 그 항목이다.
>
> 대안이었던 `QMediaPlayer.setPlaybackRate()`는 실제로 존재하지만 **택하지 않는다** — 미디어 재생용이라 지연이 크고, 효과음에서 지연은 곧 "틀린 타이밍"이다(§5.3과 같은 이유). 피치 변형 클립을 미리 만들어두는 방법은 §3에서 제외한 "사운드 큐"에 가까워지므로 역시 아니다.
>
> **값을 늘리는 게 아니라 줄이는 쪽을 택했다** — 이 문서의 철학과도 맞고, 나중에 엔진 오디오가 생겨 피치가 공짜로 가능해지면 그때 추가하면 된다.

**저장 위치**: `ActionEvent.params`에 그대로 들어간다. 자료구조도 파일 포맷도 바뀌지 않는다(§1.1).

```json
{ "frame": 12, "type": "Sound",
  "params": { "clip": "sfx/Sword_Swing.wav", "volume": 0.9, "volumeVar": 0.1 } }
```

## 3. 명시적으로 만들지 않는 것

**이 목록이 §2 목록보다 중요하다.** "필요해지면 그때 추가"가 원칙이고, 지금 미리 자리를 만들어두지 않는다.

- **3D 공간 오디오** (리스너, 거리 감쇠, 패닝, 도플러) — 이것 하나가 리스너 → 감쇠 커브 → 오클루전 → 리버브 존으로 이어지는 가장 긴 연쇄다
- **믹서 / 버스 / 그룹 볼륨** (Master·SFX·BGM 분리)
- **DSP 이펙트** (리버브, EQ, 컴프레서, 로우패스)
- **BGM/음악 재생과 크로스페이드**
- **스트리밍 재생** (긴 파일을 디스크에서 흘려보내기)
- **오디오 압축·포맷 변환 파이프라인** (임포트 시 변환/리샘플링)
- **사운드 큐 / 랜덤 클립 세트** (한 이벤트에서 여러 클립 중 랜덤 선택) — §2.2의 Pitch ±/Volume ±가 이 요구의 상당 부분을 대신한다
- **페이드 인/아웃, 재생 중 파라미터 실시간 변조**
- **다른 EventType의 런타임 발화** — `Hit`/`Effect`/`CameraShake`는 이번 범위가 **아니다.** Sound 하나만 발화시킨다(§4.2)
- **사운드 우선순위/스틸링 정책** — 보이스 상한 초과 시 §5.2대로 신규 재생을 거부하는 것으로 끝낸다

## 4. 설계 철학

### 4.1 이미 있는 자리를 쓴다 — 새 개념을 발명하지 않는다

`EventType.SOUND`, `ActionEvent.params`, `.action.json` 직렬화, `frame_changed` 배선이 전부 이미 있다(§1.1). 이 시스템이 새로 만드는 것은 **그것들을 잇는 코드**뿐이다. 새 이벤트 타입도, 새 파일 포맷도, 새 패널도 만들지 않는다.

VFX Lite가 "이펙트 하나 = 프리팹 하나"로 두어 저장/스폰/Revert를 공짜로 얻었던 것과 같은 종류의 결정이며, 여기서는 **그 전제가 이미 코드에 존재한다는 점만 다르다.**

### 4.2 발화 지점은 하나다

```text
AnimationPreviewPanel._on_tick()      # 재생 타이머가 프레임을 전진시키는 유일한 곳
        ↓
  이전 프레임 < e.frame <= 현재 프레임 인 Sound 이벤트를 찾는다
        ↓
  SoundPlayer.play(params)
```

"프레임이 바뀌는 곳"이 여러 군데면 중복 발화와 누락이 동시에 생긴다. **재생 루프만** 발화 지점으로 삼고, 나머지 경로(스크럽, 이전/다음 프레임 버튼, 타임라인 클릭)는 **소리를 내지 않는다**(§5.4).

> **개정(2026-09-10, §6.2가 (b)로 확정되면서)**: 재생 루프가 **두 개**가 된다 — Motion Editor의 `_on_tick()`과 Scene Editor Play의 재생 루프. 그래서 "프레임 전진 → 발화할 이벤트 선별"을 **재사용 가능한 조각 하나로 분리**하고 두 루프가 그것을 쓰게 한다. 발화 지점이 둘이 되는 것이지 **발화 규칙이 둘이 되는 것은 아니다**(§6.2.2).

### 4.3 오디오 백엔드는 엔진이 아니라 에디터에 둔다 (v1)

`QSoundEffect`(PySide6)를 쓴다. 엔진에 오디오 서브시스템을 만들지 않는다.

- 사운드 저작에서 가장 자주 하는 일은 **"이 프레임에 이 소리가 맞나"를 반복 확인**하는 것이고, 그건 에디터에서만 돼도 대부분 해결된다.
- 엔진 오디오 백엔드는 §3의 제외 목록(3D/믹서/DSP)을 부르는 진입로다. **지금 만들면 지금 그 연쇄가 시작된다.**
- 버릴 때 비용이 작다 — 재생 호출부가 한 곳(`SoundPlayer`)이므로, 나중에 엔진 오디오가 생기면 그 안쪽만 바꾼다.

> **중요한 부작용(좋은 쪽)**: 이 에디터는 Play Mode도 **같은 프로세스** 안에서 돈다(그래서 창 클래스 충돌이 났던 것 — §1.1). 따라서 QtMultimedia로 낸 소리는 **Play Mode에서도 그대로 들린다.** "플레이에서 확인"이 엔진 오디오 없이도 가능할 수 있다는 뜻인데, 남는 문제는 "재생 중 이벤트를 누가 발화시키는가"다 — §6.2의 미해결 항목.

### 4.4 임포트는 참조만 한다 — 파일을 복사하거나 변환하지 않는다

GUI에서 오디오 파일을 고르면 **경로만** `params.clip`에 넣는다. 프로젝트 폴더로 복사하지도, 포맷을 변환하지도, 메타데이터를 만들지도 않는다.

§3의 "오디오 압축·포맷 변환 파이프라인"을 제외한 것과 같은 이유다 — 임포트가 "변환"을 시작하는 순간 그건 에셋 파이프라인 프로젝트가 된다. VFX Lite §6.1에서 텍스처 로더를 만들지 않기로 한 것과 정확히 같은 판단이다.

## 5. 비용 철학 — "비싸질 수 있는 경로를 만들지 않는다"

### 5.1 엔진에 오디오 서브시스템을 만들지 않는다
§4.3. v1에서 이것 하나를 안 만드는 것이 가장 큰 절약이다.

### 5.2 동시 재생 보이스 상한 (엔진 정책, 파라미터 아님)
동시에 울리는 소리 개수에 상한을 둔다. 초과 시 **신규 재생을 거부**한다 — 이미 나고 있는 소리를 끊지 않는다.

VFX Lite §5.2의 "Max Particle 초과 시 신규 생성 거부, 순환 버퍼 금지"와 같은 결정이며 이유도 같다: 재생 중인 소리를 중간에 끊는 것이 가장 티가 나는 실패 방식이다. 이 상한은 **§2의 5개 값에 추가하지 않는다** — 이벤트 하나가 조절할 값이 아니라 엔진 정책이다.

### 5.3 클립은 미리 로드해두고 재생 시점에 디스크를 건드리지 않는다
액션을 열 때 그 액션이 쓰는 클립을 한 번 로드하고, `_on_tick()` 안에서는 **파일 I/O도 디코딩도 하지 않는다.** 재생 시점에 디스크를 읽으면 소리가 프레임보다 늦게 난다 — 사운드에서 지연은 곧 "틀린 타이밍"이다.

### 5.4 스크럽 중에는 소리를 내지 않는다
타임라인을 드래그하면 프레임이 초당 수십 번 바뀐다. 그때마다 소리가 나면 쓸 수 없다. **재생(`_on_tick`) 중에만** 발화한다(§4.2).

### 5.5 같은 이벤트를 한 번의 재생에서 두 번 발화하지 않는다
프레임이 되감기거나(루프) 같은 프레임에 두 번 들어오는 경우에 중복 발화하지 않는다. 루프 경계에서 소리가 두 번 겹치는 것은 가장 흔한 증상이다.

### 5.6 클립 로딩 실패가 재생을 막지 않는다
파일이 없거나 포맷이 안 맞으면 **그 이벤트만 조용히 건너뛰고 로그를 남긴다.** 액션 재생 자체가 멈추면 안 된다 — 사운드는 곁다리이지 본체가 아니다.

### 5.7 확정 체크리스트

- [ ] 새 이벤트 타입/파일 포맷/패널을 만들지 않는다 — 기존 `EventType.SOUND` + `ActionEvent.params` + `.action.json`을 쓴다(§4.1)
- [ ] 발화는 **재생 루프에서만** 일어난다. 루프는 둘(Motion Editor / Scene Editor Play)이지만 **발화 규칙은 하나의 공통 조각**을 공유한다(§4.2, §6.2.2)
- [ ] v1의 오디오 백엔드는 `QSoundEffect`다 — 엔진에 오디오 서브시스템을 만들지 않는다(§4.3)
- [ ] 임포트는 경로 참조만 한다 — 복사·변환·메타데이터 없음(§4.4)
- [ ] 동시 보이스 상한을 두고, 초과 시 신규 재생을 거부한다(§5.2)
- [ ] 클립은 미리 로드하고 재생 시점에 파일 I/O를 하지 않는다(§5.3)
- [ ] 스크럽/버튼 이동에서는 소리를 내지 않는다(§5.4)
- [ ] 루프 경계에서 중복 발화하지 않는다(§5.5)
- [ ] 클립 실패가 액션 재생을 멈추지 않는다(§5.6)
- [ ] 3D/믹서/DSP/BGM/큐는 만들지 않는다(§3)

## 6. 미해결 — 착수 전에 결정할 것

### 6.1 게임 빌드 사운드 — ✅ **v1 제외로 확정 (§6.2가 (b)로 정해지면서 따라 결정됨)**

§6.2에서 (b)를 택했다 = **엔진에 이벤트 런타임도 오디오 백엔드도 만들지 않는다.** 따라서 v1에서 나는 소리는 **에디터 프로세스 안에서만** 들린다. 다만 Play Mode도 그 프로세스 안에서 돌기 때문에(§4.3), **"플레이에서 확인"이라는 원래 요구는 v1에서 충족된다** — 빠지는 것은 "에디터 없이 실행되는 게임 빌드에서의 소리"뿐이다.

아래는 결정 근거로 남겨둔 비교표다.

| | v1 = 에디터까지 (권장) | v1 = 엔진 오디오까지 |
|---|---|---|
| 새로 만드는 것 | 이미 있는 것들을 잇는 코드 | + 오디오 백엔드, WAV 디코더, C++ 이벤트 런타임, `.action.json`을 읽는 C++ 경로 |
| 얻는 것 | "이 프레임에 이 소리" 저작·확인 | 게임 빌드에서도 소리 |
| 위험 | 게임 오디오는 나중에 다시 | §3의 제외 목록이 곧바로 압박받는다(3D/믹서) |

> **권장**: 에디터까지를 v1로 한다. 저작 경험이 먼저 있어야 "게임에서 어떤 오디오가 필요한지"도 실제 데이터로 판단할 수 있고, §4.3대로면 Play Mode에서도 들리므로 체감상 손실이 생각보다 작다.

### 6.2 Play Mode에서 누가 발화시키는가 — ✅ **(b)로 확정 (2026-09-10)**

§4.3의 부작용대로 Play Mode에서도 **소리는 들린다**(같은 프로세스). 그러나 Scene Editor의 Play는 `.action.json`을 읽지 않는다 — 애초에 **엔진에 Action이라는 개념이 없다**(§1.2). 지금 재생되는 것은 Motion Editor의 미리보기뿐이다.

**확정: (b) Scene Editor Play에서도 파이썬이 액션을 재생한다.** 엔진에 이벤트 런타임을 만들지 않고(=(c) 제외), Motion Editor 미리보기로 대신하지도 않는다(=(a) 제외).

> **(b)가 실제로 요구하는 것 — 정직하게 적어둔다**: (b)는 "사운드만 얹기"가 아니다. **Sound Lite가 최소한의 액션 재생 기능을 포함하게 된다.** Play Mode에서 액션이 재생되려면 "어느 엔티티가 어느 액션을 재생하는가"가 데이터로 존재해야 하고, 지금은 그것이 없기 때문이다. 이 비용을 §6.2.1에서 최소로 묶는다.

#### 6.2.1 "어느 엔티티가 어느 액션을 재생하는가" — ✅ **(b2)로 확정 (2026-09-10)**

§1.1에서 확인했듯 `AIComponent`가 이미 `idle_action`/`attack_action`/`hit_action`과 `AIState`를 갖고 있다. **그러나 이 필드를 읽는 시스템이 하나도 없다.**

| | **(b1) `AIComponent`를 그대로 쓴다** | **(b2) 작은 전용 컴포넌트를 새로 만든다 (권장)** |
|---|---|---|
| 새 컴포넌트 | 0개 | 1개 (`ActionPlayerComponent`) |
| 액션 선택 | `AIState`에 따라 3개 중 하나 | 필드에 적힌 액션 하나 |
| 딸려오는 것 | **`AIState` 상태 전이 로직** — 무엇이 Idle→Attack을 만드는가? 그건 AI 시스템이다 | 없음 |
| AI가 아닌 엔티티 | 액션을 못 쓴다(불꽃 이미터, 소품 등) | 쓸 수 있다 |

**권장은 (b2)다.** (b1)을 택하면 "Play를 눌렀을 때 이 엔티티가 왜 Attack 상태인가"에 답해야 하고, 그 답은 상태 전이 규칙 → 조건 → 타깃 탐색으로 이어진다. 그건 §3이 경계하는 종류의 연쇄이며 **사운드와 아무 상관이 없다.** VFX Lite가 고아 상태의 `engine/asset/`을 되살리는 대신 필요한 최소만 만들기로 한 것과 같은 판단이다.

(b2)를 택할 경우 컴포넌트는 **3개 필드로 끝낸다** — 이것들은 §2의 5개 사운드 값에 **추가되는 것이 아니라 별개 축**이다:

| 필드 | 의미 |
|---|---|
| `action` | 재생할 `.action.json` 경로 |
| `playOnStart` | Play 진입 시 자동 재생할 것인가 |
| `loop` | 끝나면 처음으로 되감을 것인가 |

`AIComponent`의 action 필드들은 **건드리지 않는다** — 나중에 AI 시스템이 생기면 그때 `ActionPlayerComponent`와 어떻게 연결할지 정하면 된다.

#### 6.2.2 (b)에서 발화 지점이 두 개가 된다

§4.2는 발화 지점을 `AnimationPreviewPanel._on_tick()` 하나로 못박았는데, (b)를 택하면 **Scene Editor Play의 재생 루프가 두 번째 지점**이 된다. 발화 규칙(§5.4/§5.5)은 두 곳에서 동일해야 하므로, **프레임 전진과 이벤트 발화를 하나의 재사용 가능한 조각으로 분리**해서 두 재생 루프가 같은 것을 쓰게 한다. 구현 계획서에서 이 분리를 첫 단계로 잡는다.

### 6.3 지원 오디오 포맷 — ✅ **WAV만으로 확정 (2026-09-10)**

`QSoundEffect`는 지연이 낮아 효과음에 적합하지만 **비압축 WAV만** 재생한다(Qt 문서 기준 — 착수 시 실제 확인 필요). `QMediaPlayer`는 더 넓은 포맷을 다루지만 지연이 크고 미디어 재생용이다.

**확정**: v1은 **WAV만** 지원하고, 그 제약을 임포트 UI에서 명시한다(파일 필터를 `*.wav`로). §3에서 포맷 변환 파이프라인을 제외했으므로 "다른 포맷을 넣으면 변환해준다"는 경로는 애초에 없다. `QSoundEffect`의 실제 포맷 제약은 구현 착수 시 직접 확인한다(문서 기준이지 실측이 아니다).

### 6.4 클립 경로의 기준 — ✅ **`.action.json` 파일 위치 기준 상대 경로로 확정 (2026-09-10)**

`params.clip`을 절대 경로로 두면 다른 사람 PC나 다른 폴더로 옮기는 순간 전부 깨진다. 프로젝트 루트 기준으로 두면 "프로젝트 루트가 무엇인가"를 먼저 정의해야 하는데, 현재 에디터는 CWD가 `engine/editor/`라 경로 문제를 이미 한 번 겪었다(셰이더를 파일 대신 인라인 소스로 두는 이유가 바로 그것이다 — `SceneMeshRenderer.h` 주석).

**확정**: `params.clip`은 **그 액션 파일(`.action.json`)이 있는 폴더 기준 상대 경로**로 저장한다. 새 개념(프로젝트 루트)을 도입하지 않으면서 액션과 클립이 함께 이동해도 깨지지 않는다. 액션이 아직 저장된 적 없어 기준 폴더가 없으면, 저장 시점에 경로를 다시 계산한다.
