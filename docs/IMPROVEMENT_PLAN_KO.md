## 1. 개요

### 1.1 계획 목적
문제점 분석 보고서에서 식별된 문제들을 체계적으로 해결하여 프로젝트의 안정성, 개발 생산성, 유지보수성을 향상시킵니다.

### 1.2 계획 범위
- 프로젝트 구조 최적화
- 빌드 시스템 개선
- 데스크탑 환경 호환성 강화
- 코드 품질 및 테스트 강화
- 문서화 체계화
- GUI 통합 (이중 GUI 구조 해결)
- 버그 수정 (메인 루프, 빌드 시스템, 렌더링)

### 1.3 우선순위 원칙
1. **개발 생산성**: 빌드 시간, 디스크 공간, 개발자 경험
2. **안정성**: 메모리 관리, 오류 처리, 호환성
3. **유지보수성**: 문서화, 테스트 커버리지, 코드 품질
4. **성능**: 렌더링 최적화, 메모리 효율성

## 2. 완료된 개선 사항

### 2.1 데스크탑 환경 호환성 강화 ✅
- **OpenGL 호환성**: 3단계 폴백 시스템 (4.1 Core → 3.3 Core → 3.3 Compatibility)
- **플랫폼 오류 처리**: Win32 GetLastError() 추가로 상세 오류 정보 제공
- **OpenGL 버전 로깅**: 실제 사용 중인 OpenGL 버전/렌더러 자동 출력

### 2.2 빌드 시스템 개선 ✅
- **의존성 캐싱**: FetchContent 캐싱 설정으로 빌드 시간 단축
- **의존성 업데이트 비활성화**: 안정성 향상
- **AddressSanitizer**: MSVC 2019+에서 메모리 디버깅 옵션 추가

### 2.3 빌드 진단 시스템 구현 ✅
- **환경 진단**: 시스템, 컴파일러, 플랫폼 정보 자동 출력
- **컴파일러 호환성 체크**: C++23 지원 여부 자동 검증
- **의존성 오류 처리**: 다운로드 실패 시 5가지 원인 분석 및 해결책 제공
- **시스템 요구사항 체크**: 디스크 공간, 메모리, Python 존재 여부 확인

### 2.4 빌드 전제 조건 확인 스크립트 ✅
- **Windows**: `check_build_prerequisites.ps1` - Visual Studio, CMake, Git, Python 체크
- **Linux/macOS**: `check_build_prerequisites.sh` - GCC/Clang, CMake, Git, Python 체크

### 2.5 메모리 관리 안정성 강화 ✅
- **FrameAllocator 경고 시스템**: 80% 용량 도달 시 자동 경고
- **IsNearCapacity() 메서드**: 메모리 사용량 모니터링

## 6. GUI 통합 계획 (2026-07-28 추가)

### 6.1 문제 개요

#### 6.1.1 이중 GUI 구조 문제
- **현재 상태**: 메인 GUI (GLFW+OpenGL)와 에디터 GUI (PySide6/Qt)가 별도로 존재
- **영향**: 코드 중복, 데이터 불일치, 유지보수 복잡성 증가
- **심각도**: 높음

#### 6.1.2 메인 GUI 루프 버그와 연관성
- 메인 GUI의 루프 조건 버그로 인한 GUI 통합 필요성 증대
- 독립적인 GUI 개발로 인한 버그 발생 가능성

### 6.2 통합 전략

#### 6.2.1 목표
- GLFW 기반 메인 GUI를 제거하고 PySide6 에디터를 단일 GUI로 통합
- 엔진 렌더링을 Qt 위젯에 임베딩
- 단일 진입점으로 통합

#### 6.2.2 기술적 구현 방안

**1. 엔진 렌더링 Qt 위젯 임베딩**
- QtEngineViewport 클래스 구현
- 엔진 초기화 시 Qt 윈도우 핸들 전달
- 렌더링 타이머로 60fps 프레임 렌더링

**2. 통합된 메인 에디터 구조**
- 기존 Scene Editor와 Motion Editor 유지
- 플레이 모드를 에디터 내에 통합
- QStackedWidget으로 모드 전환

**3. C++ 진입점 제거**
- main.cpp 제거 또는 레거시용으로 분리
- Python 진입점으로 완전 전환

### 6.3 마이그레이션 단계

#### Phase 1: 기술 검증 (1-2주)
- Qt 위젯에 엔진 렌더링 임베딩 테스트

- 기본 뷰포트 기능 구현

#### Phase 2: 기능 이전 (2-3주)
- 데모 씬을 에디터로 이전
- 플레이/정지 기능 통합
- config.json 로직 통합

#### Phase 3: 레거시 제거 (1주)
- GLFW 기반 main.cpp 제거 또는 레거시용으로 분리
- 의존성 정리 (GLFW 최소화)
- 문서 업데이트

### 6.4 장단점 분석

**장점**:
- 단일 GUI로 통합으로 유지보수성 향상
